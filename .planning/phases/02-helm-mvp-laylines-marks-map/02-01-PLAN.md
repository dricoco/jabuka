## Phase Goal

**As the** helmsman of the X35 (the owner, racing at night), **I want to** race to the next mark on laylines alone, with polar targets, live laylines and the course on a night-readable tablet helm view over an offline map, from live or manually entered wind, **so that** I have a guaranteed "steer this / tack here" even if routing never ships.

(Restated from the ROADMAP Phase 2 goal, which names the helmsman as the user; the ROADMAP Goal line is not in strict user-story format.)

- [ ] The core serves the offline race pack (tiles, seamarks, coastline, info) and the page renders the map from vendored assets with laylines over it, fully offline

1. Package src/jabuka/nav/ (pure: no clock reads, time is passed in; file I/O only through atomicio in course.py and settings.py).
   - geo.py: local equirectangular frame around a reference point in nm (x east, y north, x = dlon * cos(lat0) * 60, y = dlat * 60), the inverse, bearing_distance (true bearing in rad and distance in nm), offset(lat, lon, bearing_rad, dist_nm), unit vector helper.
   - polar.py: the Polar dataclass of per-TWS curves (Expedition semantics, RESEARCH Pattern 3). speed() folds |TWA| into [0, 180], interpolates linearly in TWA within each bracketing TWS curve then linearly across TWS, adds an implicit (0°, 0 kn) point and an implicit all-zero TWS 0 curve, clamps above the highest TWS. targets() finds max upwind VMG over a 0.5° grid in [25, 90] and max downwind VMG (-bsp·cos) over [90, 180], cached per TWS rounded to 0.1 kn. parse_expedition accepts "!" comments and lines "TWS (TWA BSP)+" separated by tabs or spaces and rejects non-finite or negative numbers with ValueError. polar_from_json/polar_to_json use {"name", "source", "curves": [[tws, [[twa, bsp], ...]], ...]}. load_racepack_polar(dir) loads dir/polar.json when it parses and validates, else default_polar(), and reports which one was used.
