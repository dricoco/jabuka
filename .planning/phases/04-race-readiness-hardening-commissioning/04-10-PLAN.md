## Deferred findings (explicit, with rationale)

| Finding | Decision | Rationale |
|---|---|---|
| `asyncio.to_thread` at each call site | Not used (an equivalent is chosen) | The callers are synchronous: CourseStore runs inside the tick, router_service writes bias.json inside the tick, and the stores are shared with the tick. Moving them to `to_thread` would need locks around the stores, and a held lock would block the tick again. Its multi-threaded executor would also lose the per-file write order. One FIFO thread keeps the rename order with no caller change. |
| An API 200 now comes before the fsync completes | Accept (documented) | The temp write is synchronous, so the data is in the page cache and every crash-safety invariant holds (never a torn file, .bak kept, rename after fsync). A power cut within the stall window loses only the last change, which is the same as a crash just before the request. drain() covers clean shutdowns. |
| Background failure (EIO on fsync/rename after a successful temp write) has no tablet alert | Accept | Logged (journal) and counted in Diag core `bg_write_errors`. The common full/read-only disk cases still fail synchronously with the existing 503 / alert. Adding a nav alert would need new i18n strings in the UI plans' files. |
| Review B LOW items (tile threadpool, retention mtime, task supervision, gpsd mode, allow_nan, derived log size) | Defer (review) | Out of the owner's gap list. |

jabuka.common.atomicio:
- WORKER_NAME = "jabuka-durable".
- enable_background() -> None: process-wide on, idempotent. The daemon worker thread starts lazily on the first job.
- disable_background(timeout_s: float = 20.0) -> bool: drain(timeout_s), then off. Returns the drain result.
- background_enabled() -> bool.
- drain(timeout_s: float) -> bool: True once no job is queued or running. threading.Condition.wait_for, no clock read.
- background_status() -> dict: {"enabled": bool, "pending": int, "errors": int, "last_error": str | None}.
- fsync_fd(fd: int, on_done: Callable[[], None] | None = None) -> None:
  - background off: os.fsync(fd), on_done() in finally (errors propagate, as today);
  - on: dup = os.dup(fd) on the caller, then a queued job os.fsync(dup), os.close(dup), on_done() in finally. Job errors are logged and counted, never raised.
- atomic_write_bytes(path, data):
  - background off: exactly today's code;
  - on: first `_sweep_orphans(path)`. Then tmp = NAME's dir / f".{NAME}.{n}.tmp" (n from a module itertools.count), opened "xb", fully written and closed on the caller. On OSError: unlink the tmp (missing_ok) and re-raise. Then queue _finish_atomic(tmp, path): fsync(tmp via os.open O_RDONLY), .bak link + replace (same .NAME.bak.tmp dance), os.replace(tmp, path), _fsync_dir(parent). On any exception: log.exception, errors += 1, last_error = repr, unlink the tmp.
- _sweep_orphans(path) (private): under a module threading.Lock (_sweep_lock, separate from the queue's Condition), when str(path) is not yet in the module set _swept, add it and unlink (missing_ok, OSError logged and ignored) every entry of the parent directory named f".{NAME}.<digits>.tmp" (os.scandir plus a startswith/endswith/isdigit filter, no glob). Only numbered temps match: the sync .NAME.tmp and .NAME.bak.tmp are left alone. _swept is never cleared (a handful of state files per process; clearing it after a timed-out drain could let a re-enabled writer remove a still-queued temp). The sweep runs once per file per process, before that process creates any temp for the file, so it only ever removes a previous run's orphans.
