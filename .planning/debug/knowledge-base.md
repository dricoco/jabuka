## soak-route-not-refreshed — Pi system-scope soak FAIL: "no new route (version > N)", grib-gap ValueError, manual CHANGED by a clean pull, keepalive AssertionError
- **Date:** 2026-11-10
- **Error patterns:** no new route (version > 114) within 60 s, no optimal route after On reste was switched off, route_after_recovery missing, refusing to touch ... racepack: outside the soak run dir, manual CHANGED by a clean pull, AssertionError keepalive ping failed _drain_helper assert waiter is None or waiter.cancelled(), recovery_gps/recovery_process/recovery_power NON, soak race-36h system scope
- **Root cause(s):** harness baseline tablet.max_route_version() = run-wide max while a core restart (course changed) legitimately renumbers routes from 1 (routes were in fact refreshed 4-15 s after each fault; not an app defect, under-voltage not involved); Harness.write_full_wind used run_dir instead of state_root as the pack guard root (system scope keeps the pack under /var/lib/jabuka/soak-<ts>); power_pull SIGKILLed 0.3-0.5 s after POST /api/wind/manual, inside the core's documented background-durability window (atomicio G-4-R05); uvicorn legacy websockets keepalive ping asserts on a client stalled > ws_ping_interval (20 s) during 30-s ws-stall faults (benign)
- **Fix:** last_route_version() as the "before" baseline in every fault; write_full_wind under state_root; power_pull waits (<= 10 s) for wind_manual.json on disk to equal the acknowledged value, records manual_durable_s, fails otherwise; race-36h.json expected_tracebacks["ws-stall"] for the legacy keepalive AssertionError. No app change. Post-race follow-ups: uvicorn ws='websockets-sansio'; route.js nav fallback `v !== drawn` after a same-number restart; garbage settings.json left after f11 in the soak.
- **Files changed:** src/jabuka/soak/tablet.py, src/jabuka/soak/faults.py, src/jabuka/tools/soak.py, src/jabuka/soak/scenarios/race-36h.json, tests/soak/test_soak_faults.py
- **Why not caught:** no gate existed for this class: no fake-harness tests of the fault functions; CI soak runs user scope (pack under run_dir), short ws-stalls, fast disk; first full system-scope Pi soak was the first gate able to see it
- **Recurrence guard:** tests/soak/test_soak_faults.py (13 tests, commit 35a61a7) incl. test_course_change_after_a_renumbering_restart_sees_the_new_route, test_full_wind_is_restored_under_the_state_root, test_clean_pull_waits_for_the_acknowledged_manual_wind_on_disk, test_race_36h_keepalive_rule_expects_nothing_else; runtime manual_durable_s check in faults.power_pull; this KB entry. Status: resolved — verified by Pi race-36h soak n°3 20261111T005058Z (code 0c582d6, PASS, 131 of 131 checks; route after fault worst 15.19 s over 23 faults, power-pull and persistence OK)

## soak2-land-crossing-f67 — Pi system-scope soak FAIL: adopted route "crossing land" (v121 segment 4) + f67 "course finished during the fault, no new route (version > 129)"
- **Date:** 2026-11-11
- **Error patterns:** check land: N adopted routes re-validated; crossing land: versions [121] at segments [4], land crossings 1 of 291, start_in_margin True, bad_index, course finished during the fault: next course selected, no new route (version > 129) within 60 s, route_after_recovery missing, course B finished at sim ... s: A selected (false), soak race-36h system scope
- **Root cause(s):** S1 harness false positive: tablet._validate re-validated the core's published coordinates (route_message rounds lon/lat to 6 decimals, up to 6.87 cm off the router-validated polyline) with the exact raster check at zero tolerance; a delivered segment grazing the 100 m dilated land margin by mm/cm flips to "blocked" once rounded (reproduced 3-4 times in 4800 routes, raw land >= 92 m away; the router validates exactly what it delivers, the route follower and route.json use the unrounded path). S2 harness: (a) "before" baseline = last route message seen (v129 from a replaced core process) instead of the version the core currently shows (0, no_course); (b) course_upkeep acted on a stale "finished" nav and switched back the course the fault had just selected (false "course B finished"); (c) wait_sim only called course_upkeep when ahead of schedule, so a finished course stayed finished for ~1930 sim-s. Routing did not stall (v1 adopted 36.3 s after selection, budget 60 s). No app defect.
- **Fix:** harness only (commit 0c582d6): tablet.py COORD_DECIMALS = 6, publication_precision_nm(frame), graze_depth_nm() (cm-sampled depth of a segment into blocked cells), _published_ok() tolerates only grazes no deeper than the publication precision, records graze_m + detail; last_route_version() = nav.route.version of the latest nav (fallback: last adopted route). tools/soak.py course_upkeep() requires finished in GET /api/course and returns True when it selected; wait_sim() calls it once even when behind schedule. faults._route_after notes "next course selected" only when a selection happened.
- **Files changed:** src/jabuka/soak/tablet.py, src/jabuka/tools/soak.py, src/jabuka/soak/faults.py, tests/soak/test_soak_tablet.py, tests/soak/test_soak_faults.py, tests/soak/test_soak_tracer.py
- **Why not caught:** no gate existed for this class: the land re-validation had no test against the core's published precision, and the course-change fault had no fake-harness test with a restart + finished course + behind-schedule planner; the cm-graze rate (~0.08 % of routes) only shows over the ~300 routes of a full race-36h soak
- **Recurrence guard:** tests/soak/test_soak_tablet.py (test_a_rounding_graze_of_the_published_route_is_not_a_land_crossing, test_only_a_graze_within_the_publication_precision_is_tolerated [7 cases], test_publication_precision_in_the_race_frame, test_the_core_publishes_route_coordinates_at_the_tolerated_precision); tests/soak/test_soak_faults.py (test_last_route_version_is_the_one_the_core_shows_now, test_course_change_on_a_finished_course_after_a_restart_sees_route_1, test_course_upkeep_ignores_a_stale_finished_nav, test_course_upkeep_selects_the_other_template_of_a_finished_course, test_wait_sim_behind_schedule_still_keeps_the_course_going); graze_m recorded in the soak report detail ("within the publication rounding"); this KB entry. Status: resolved — human-verified on Pi soak n°3 20261111T005058Z (PASS: land 0 of 315, 2 grazes within rounding, deepest 0.0163 m; f67 13.5 s; route after fault worst 15.19 s over 23 faults)
