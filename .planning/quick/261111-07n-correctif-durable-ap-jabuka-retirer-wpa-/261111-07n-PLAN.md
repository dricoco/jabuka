<objective>
Make the field workaround for the "jabuka" access point permanent in the deployment, so that the tablet and the phone can join the Pi's AP after every boot, provision run and Wi-Fi switch, with no manual wpa_cli step on the boat.

Root cause (proven on the Pi with wpa_supplicant debug logs, do not re-investigate): on the Pi 3B (NetworkManager 1.52.1, wpasupplicant 2.10-24+rpt3, brcmfmac firmware without MFP/FWSUP/SAE), NetworkManager hands wpa_supplicant `key_mgmt="WPA-PSK WPA-PSK-SHA256"` (nl80211 key_mgmt_suites=0x102) even with `wifi-sec.pmf disable` (deploy/provision.sh, AP_PROPS). The firmware beacons its own RSN IE (PSK only) while message 3/4 of the 4-way handshake carries wpa_supplicant's RSN IE (PSK + PSK-SHA256): the mismatch makes clients (Android 11 tablet, phone) disassociate right after M3 (M2 MIC is OK, so the passphrase is right). Verified manual fix on the Pi: `wpa_cli -i wlan0 set_network 0 key_mgmt WPA-PSK; wpa_cli -i wlan0 disconnect; wpa_cli -i wlan0 select_network 0` -> AP-STA-CONNECTED for both clients, and `wpa_cli -i wlan0 status` then shows `key_mgmt=WPA2-PSK`.

Purpose: core value at the helm needs the tablet on the AP (DATA-01). The fix must survive power cycles and 36 h unattended, and must never break NetworkManager.
Output: a NetworkManager dispatcher script in deploy/, installed by provision.sh, its tests, the provision dry-run assertions, a jabuka-wifi comment, and the PI-SETUP.md verify/troubleshooting update. No src/ change (the src/jabuka freeze fingerprint is untouched). Nothing is deployed: a soak runs on the Pi, deployment happens later, outside this task.
</objective>

NetworkManager dispatcher contract (scripts in /etc/NetworkManager/dispatcher.d/, run in lexical order by NetworkManager-dispatcher.service, D-Bus activated):
- argv: $1 = interface name (e.g. wlan0; "none" for hostname events), $2 = action (pre-up, up, pre-down, down, dhcp4-change, hostname, connectivity-change, reapply, ...).
- env: CONNECTION_ID (profile name, e.g. jabuka-ap or jabuka-phone; unset for hostname/connectivity-change), CONNECTION_UUID, DEVICE_IFACE, NM_DISPATCHER_ACTION. The environment is built by nm-dispatcher itself; PATH may be absent or minimal, and Debian's bash default PATH has no sbin dirs (wpa_cli is /usr/sbin/wpa_cli).
- The script is ignored unless it is owned by root, not writable by group or other, not setuid, and executable. Plain dispatcher.d/ scripts receive "up" (pre-up needs pre-up.d/, not used here). Scripts of one event run serially, so a long script delays later events: keep the wait bounded.

wpa_cli (non-interactive, with an explicit `-i wlan0`, so no "Selected interface" line):
- `wpa_cli -i wlan0 list_networks` prints the header `network id / ssid / bssid / flags`, then one TAB-separated row per network: `<id>\t<ssid>\t<bssid>\t<flags>`, e.g. `0\tjabuka\tany\t[CURRENT]`.
- `wpa_cli -i wlan0 get_network <id> key_mgmt` prints the value, e.g. `WPA-PSK WPA-PSK-SHA256`; `FAIL` on error.
- `set_network`, `disconnect`, `select_network` print `OK` on success, `FAIL` otherwise. A `FAIL` reply may still exit 0, so success = exit 0 AND output `OK`.
- Without a control socket it prints `Failed to connect to non-global ctrl_ifname: wlan0  error: ...` and exits non-zero (255).
